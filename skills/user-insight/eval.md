# 用户洞察 eval（stub）

> 触发条件：该 skill 被反复使用、需要质量闸时补全。当前精简优先，先 stub 不镀金。

## 验收要点（占位）

1. **洞察来自证据**：A 类假设是否站在访谈/观察上，而非同理心想象？
2. **stated vs revealed**：是否区分用户说的与用户做的/情境，后者权重更高？
3. **样本量透明**：孤例是否标清，没被当成规律？
4. **不越界**：产出是否停在"带证据的 A 类假设"，未跳到方案/MVP/排期？
5. **下一步指向红队**：收尾是否交接给 @assumption-xray，而非产品动作？

补全时参考 assumption-xray/eval.md 的写法（5 条 + ✅/❌ 对照）。
