# 竞品拆解：从对手身上读市场真相

## Purpose

评审 $ARGUMENTS（竞品或替代方案）。不是做功能对照表，而是读出**市场已经验证了什么、还留着什么缺口**，并把它变成你的 B/C 类假设。**目标是找到可防守的差异，而不是罗列谁有什么按钮。**

## Context

- 主要产出 **B 商业可行 / C 技术可行** 类假设。
- 最强的替代方案常常不是“同类产品”，而是**用户现在的凑合方案**（Excel、Slack、什么都不做）。
- 竞品存在本身 = 市场信号（L2 间接证据）；它们的定价/留存/评价 = 更强证据。
- **内核回路位置**：本 skill 与 user-insight 并列为回路的**入料口**（产 B/C 类假设）。产出同样是待红队的原料，下一站是 `@assumption-xray`，不是去把差异化功能造出来。

## Instructions

> **动手前先回显当前项目**：先声明 `当前项目: workspace/<slug>/`，确认它就是本次要读写的项目。若同一会话此前在操作别的项目，先提示开新会话或让用户确认切换，再继续。本次所有读写只落在这个目录内。

1. 读 thesis，锁定要防守的价值主张。
2. 列出 3–5 个竞品/替代方案，**包含“不用任何工具”的现状**。
3. 每个拆：真正解决的核心任务 / 定位人群 / 定价模式 / 明显缺口 / 用户为什么留下或离开。
4. 先 steelman 最强竞品：如果用户已经用它且满意，你凭什么进来？
5. 提炼**市场缺口**与**差异化假设**，转成可证伪的 B/C 类陈述。
6. 标影响与证据等级（竞品官网/评价=indirect→L2；你亲自试用=direct→L3）。
7. **收尾只交接给内核回路**：B/C 类假设回写台账后，建议下一步 = `@assumption-xray` 红队，或 `@evidence-intake` 补亲自试用证据。**不得把“差异化下一步”写成“去做这个功能/MVP”。**

## Output

```
## 竞品拆解：[市场/品类]

### 竞品矩阵（含“现状凑合方案”）
每个：核心任务 / 定位 / 定价 / 缺口 / 留存或流失原因

### 最强替代方案的 steelman
[如果用户已经满意，你的进入理由是什么]

### 市场缺口 → 差异化假设
- B/C 类可证伪假设 + 影响 + 证据等级

### 无法判断
[需要亲自试用/数据才能确认的空白]

### 下一步（回路内）
交给 @assumption-xray 红队 B/C 类假设（或 @evidence-intake 补试用证据）
```

## Kernel Write-back

- B/C 类假设按 schema 映射，`id` 留空交 validator。
- `provenance.reliability` 据实（试用=direct，二手=indirect），`evidenceLevel` ≤ 上限。
- `≥L3` 需 `/review` sign-off。
- 落库前跑 `node tools/validate.mjs`。

## Notes

- 不做无差别功能清单；每条都要回答“这对我的决策意味着什么”。
- 别低估“什么都不做”这个竞品。
- ❌ **不要把差异化机会直接当成“该做的功能”去建 MVP/原型。** 市场缺口是假设，不是结论；未经 `@assumption-xray` 红队 + sign-off 前，不得建议进入方案/排期。
- “下一步”永远指向内核回路的下一个节点，不是产品动作。
