# /retro — 复盘决策校准

触发：用户说"复盘上次决策"/"校准我的判断"/"上次那个 go 决定现在看怎么样"→ 进本流程。

`/retro` 回头看过去的 go/pivot/kill 决定，用 **git-SHA 快照** 取回当时的假设分布，对照现在的结果。它的价值不是"判断对不对"，是**暴露事后合理化**——"我早就知道 A-01 没问题"这种自欺。

## 红线（先于流程）

1. **只读不评**——/retro 取快照、对照、读反事实，**不输出"判断准确率"或"决定对不对"**。校准是过程纪律，不是结果正确性。
2. **不自动打分**——校准质量依赖 xray kill 标准带数字（killCriteria 是否可证伪）。如果当时 kill 标准是模糊线，/retro 算出的就是噪声，如实标注。
3. **反事实只读回**——go 时写死的反事实字段，/retro 只负责读回来对照，不做事后重新解释。

## 流程

1. 回显当前项目：确认 `workspace/<slug>/`。
2. 读 `decisions.md`，列出所有 go/pivot/kill 决策。若无决策记录 → 提示"先跑 /decide"。
3. 对每条决策：
   - **取快照**：读 `git SHA` 行 → `git show <SHA>:workspace/<slug>/ledger.json` 取回当时假设分布。
     - 若 SHA 为 `n/a` 或缺失 → 标注"⚠️ 快照缺失，此决策无法回溯校准"（这是 /decide 没留 SHA 的已知缺口，如实报告，不编造）。
   - **对照现在**：读当前 `ledger.json`，列出每条触发假设从"当时状态"→"现在状态"的变化。
   - **读反事实**：读 `反事实` 行，对照"若仍裸奔假设被推翻，决定是否仍成立"——看现在是否真被推翻了。
4. 输出校准报告（格式见下）。
5. **不指向回路动作**——/retro 是复盘，不触发新验证或修订。若用户想据此改论点 → 引导 `@revise-thesis`（但那是用户主动决定，不是 /retro 自动路由）。

## 输出格式

```
## 决策校准报告 — <项目> · <日期范围>

### 决策 1: <日期> — <go/pivot/kill>
- 快照: <SHA 或 ⚠️ 缺失>
- 当时假设分布:
  | 假设 | 当时状态 | 当时证据 | 现在状态 | 现在证据 |
  |---|---|---|---|---|
  | A-01 | validated | L3 | validated | L3 |
  | B-01 | todo(裸奔) | L1 | todo(裸奔) | L1 |
- 反事实对照: "若 B-01 被推翻，此决定是否仍成立？" → B-01 现在状态: <仍未测/已验证/已推翻>
- kill 标准质量: <可证伪数字 / ⚠️ 模糊线>

### 校准信号（不评分）
- 仍裸奔的承重假设: <数量>（go 后至今未测的）
- kill 标准带数字的决策比例: <n/m>
```

## 说明

- **过程校准 ≠ 结果校准**：/retro 校准的是"假设→证据的判断链质量"（验证速度够不够快、kill 标准够不够硬），**不是"产品决策对了没"**（Reckoner 不收集上线后数据，无法回答这个）。
- **kill 标准依赖**：/retro 的校准信号质量上游依赖 xray 的 killCriteria 是否带数字阈值。模糊 kill 标准（"反馈不好"）= 噪声，如实标注。
- **git-SHA 是地基**：/decide 时留的 SHA 是 /retro 取回"当时假设分布"的唯一途径。没留 SHA 的决策无法校准——这正是 /decide 第 5 步强制 commit + 填 SHA 的理由。
- **不入内核 schema**：/retro 只读不写，不改 ledger.json/thesis.md，不经 validate.mjs。产出是报告，不是回写。
