## 1️⃣ 商业模式设计

目标：想清楚产品如何创造价值、传递价值、捕获价值

### 核心框架

商业模式画布（Business Model Canvas）

```
关键伙伴  关键活动  价值主张  客户关系  客户细分
          关键资源            渠道通路
              成本结构    收入来源
```

> 产品经理不需要设计整个 BMC，但必须深度理解「价值主张」「客户细分」「收入来源」三格

价值主张画布（Value Proposition Canvas）

```
        产品侧                    用户侧
  ┌─────────────┐          ┌─────────────┐
  │  Products   │          │  Customer   │
  │  & Services │  ←匹配→  │    Jobs     │
  │  Pain       │          │    Pains    │
  │  Relievers  │          │    Gains    │
  │  Gain       │          │             │
  │  Creators   │          │             │
  └─────────────┘          └─────────────┘
```

> 核心动作：产品的痛点缓解 ↔ 用户的痛点 是否精准对齐

### 商业模式类型判断

|模式|典型形态|关键指标|
|---|---|---|
|订阅制 SaaS|按月/年收费|MRR、Churn、LTV|
|交易佣金|平台抽成|GMV、Take Rate|
|广告变现|流量变现|DAU、eCPM、填充率|
|免费增值 Freemium|基础免费+付费升级|转化率、付费渗透|
|硬件+服务|设备低价引流|复购率、ARPU|

### 定价策略

- ​价值定价​：基于用户感知价值而非成本
- ​竞争定价​：参考市场锚点，差异化定位
- ​分层定价​：Free / Pro / Enterprise，覆盖不同支付意愿
- ​心理定价​：99 vs 100，年付 vs 月付转化差异

## 2️⃣ 产品定位与差异化

目标：在用户心智中占据清晰、独特的位置

### 定位框架

经典定位公式

```
对于 [目标用户]
他们面临 [核心问题/需求]
我们的产品是 [产品类别]
它能帮助 [核心价值]
不像 [主要竞品]
我们 [关键差异化]
```

定位三问

> 1. 我们为谁服务？（聚焦，拒绝服务所有人）
> 2. 我们解决什么问题？（比竞品更深刻）
> 3. 为什么是我们？（差异化护城河）

### 差异化策略

价值曲线分析（蓝海战略）

```
竞争要素  竞品A  竞品B  我们
功能丰富度  ●●●   ●●●   ●●
易用性     ●●    ●     ●●●●
价格       ●●●   ●●    ●
垂直深度   ●     ●     ●●●●
```

> 核心动作：​消除 / 减少 / 增加 / 创造​，找到自己独特的曲线形态

差异化来源分析

|维度|举例|
|---|---|
|功能差异|独有能力、技术壁垒|
|体验差异|更简单、更快、更美|
|场景差异|细分人群、垂直行业|
|商业差异|定价模式、交付方式|
|生态差异|网络效应、平台锁定|

## 3️⃣ 战略规划与路线图

目标：将战略意图转化为可执行的方向与节奏

### 战略分析工具

> 📌 工具选择说明：传统 MBA 框架（SWOT、波特五力、Ansoff）适合向管理层汇报、传统行业转型、宏观行业判断，但对互联网/科技产品的实操指导较弱。本节按"传统框架（参考）+ 现代框架（主力）"组织，按情境选择使用。

#### 传统框架（参考，适合汇报与宏观判断）

SWOT × 战略矩阵

```
        外部机会(O)      外部威胁(T)
内部    SO战略：         ST战略：
优势(S) 利用优势抓机会    用优势对抗威胁

内部    WO战略：         WT战略：
劣势(W) 借机会弥补劣势    防守收缩保底线
```

波特五力：判断行业吸引力和竞争强度

- 新进入者威胁 / 替代品威胁 / 供应商议价 / 买家议价 / 同业竞争

Ansoff 矩阵：增长路径选择

```
            现有市场      新市场
现有产品    市场渗透      市场开发
新产品      产品开发      多元化
```

> 对 PM 最实用：清楚自己当前处于哪个象限，对应的风险和资源要求完全不同

#### 现代框架（主力，适合科技产品实操）

**Lean Canvas（精益画布）—— 0→1 产品的战略载体**

> 相比 BMC，Lean Canvas 强制填写"不公平优势（Unfair Advantage）"，更适合从 0 到 1 的产品。BMC 适合成熟业务的商业模式梳理。

```
问题           解决方案        关键指标
（Top 3 痛点）  （Top 3 方案）  （关键行为）

不公平优势      渠道通路
（难以复制的）   （如何触达用户）

客户细分        成本结构        收入来源
（早期采用者）   （固定+可变）    （盈利模式）
（早期采用者理由）
```

> 核心动作：诚实填写"不公平优势"。如果是"我们更努力""团队更强"——这不构成护城河，要找真正难以复制的东西（数据、关系、专利、网络效应、品牌）。

**7 Powers（七种武器）—— 护城河定位**

> Hamilton Helmer 的框架，帮助识别产品的核心护城河。一个产品通常只有 1-2 种 Power，不要贪多。

| Power | 含义 | 科技产品典型 |
|---|---|---|
| Scale Economies（规模经济） | 单位成本随规模下降 | 云计算、物流网络 |
| Network Effects（网络效应） | 用户越多价值越大 | 社交、交易平台、IM |
| Counter-Positioning（反向定位） | 用新模式让 incumbents 难以跟进 | Netflix vs Blockbuster |
| Switching Costs（转换成本） | 用户离开成本高 | 企业 SaaS、ERP |
| Branding（品牌） | 信息成本降低 | 消费品、奢侈品 |
| Cornered Resource（独占资源） | 独占关键资源 | 数据、专利、牌照 |
| Process Power（流程能力） | 组织流程难以复制 | 丰田生产、字节算法 |

> 实操：列出你的产品可能具备的 Power，诚实评估是真 Power 还是伪 Power。多数产品初期没有 Power，靠速度和聚焦取胜，Power 是中后期才形成的。

**Wardley Mapping（沃德利地图）—— 战略动态演进**

> Simon Wardley 的框架，分析价值链各组件的演进阶段，判断"自研 vs 采购 vs 等待基础设施化"。在 AI 时代尤其重要——判断自己做的功能是否会被基础大模型直接覆盖。

```
演进方向：Genesis（诞生）→ Custom（定制）→ Product（产品化）→ Commodity（基础设施化）

价值链地图示例：
                                    ↑ 高可见度（用户感知）
用户需求：自动化客服
    │
    ├── 对话界面      [Product]      ← 自研或用成熟产品
    ├── 对话逻辑编排  [Custom]       ← 核心差异化，自研
    ├── LLM 推理     [Product]       ← 用第三方 API
    └── 知识库构建    [Custom]       ← 数据壁垒，自研
                                    ↓ 低可见度（基础设施）
```

判断原则：

```
Genesis / Custom 阶段：
  └── 差异化机会大，值得自研投入
  └── 但风险高，可能方向错误

Product 阶段：
  └── 已有成熟产品，买比自研划算
  └── 关注集成成本与锁定风险

Commodity 阶段：
  └── 已基础设施化（如云、数据库、大模型 API）
  └── 默认采购，把精力放在上层差异化
  └── 例外条件（满足任一可考虑自研）：
       ├── 数据主权：合规要求敏感数据不能出本地
       ├── 成本：用量极大，采购成本远高于自研摊销
       ├── 性能：通用方案无法满足特殊性能要求
       ├── 供应风险：供应商可能断供或涨价，需备份
       └── 核心差异化：该环节本身就是产品护城河
  └── 自研决策需明确 ROI 测算与退出机制
```

> AI 时代特别提醒：当大模型能力覆盖你的某个功能时，该功能正快速从 Custom/Product 向 Commodity 演进。要持续审视价值链地图，避免在即将基础设施化的环节重投入。这与 [[09 AI 产品方法论#与经典方法论的映射]] 的护城河重构呼应。

### 目标体系搭建

OKR 结构

```
Objective（定性方向）
└── KR1：可量化的关键结果
└── KR2：可量化的关键结果
└── KR3：可量化的关键结果
```

> OKR ≠ KPI，O 要有野心和方向感，KR 要能验证 O 是否达成

北极星指标（NSM）选择原则

- 反映用户获得的核心价值
- 与长期商业成功正相关
- 全团队可以理解和影响
- 典型例子：Airbnb → 订房夜数 / Spotify → 收听时长

### 路线图规划

路线图的本质不是排期表，而是战略沟通工具

三层路线图

```
战略层（Now / Next / Later）
    ↓
主题层（按战略主题聚合，非功能列表）
    ↓
交付层（季度 Epic 级别，非需求明细）
```

优先级框架对比

|框架|公式|适用场景|
|---|---|---|
|ICE|Impact × Confidence × Ease|快速排序|
|RICE|Reach × Impact × Confidence ÷ Effort|较严谨的评估|
|Value vs Effort|2×2 矩阵|可视化决策|
|MoSCoW|Must/Should/Could/Won't|版本范围界定|

## 4️⃣ Stakeholder 对齐

目标：确保战略在组织中被理解、认同、支持

### Stakeholder 管理矩阵

```
         高影响力
            │
  密切合作  │  重点管理
（Keep      │  （Manage
 Satisfied）│  Closely）
────────────┼────────────
  监控跟踪  │  保持告知
（Monitor） │  （Keep
            │  Informed）
            │
         低影响力
    低关注度        高关注度
```

### 战略对齐的关键动作

向上对齐（管理层）

- 用商业语言而非产品语言：ROI、市场份额、战略卡位
- 提供决策选项而非单一方案：展示 Option A/B/C 的取舍

向外对齐（跨部门）

- 战略简报（Strategy Brief）：一页纸说清楚方向和逻辑
- 定期战略同步节奏：Season Planning → Monthly Review

产品战略文档结构

```
1. 背景与现状
2. 我们的机会
3. 我们的选择（做什么 / 不做什么）
4. 成功定义（指标）
5. 关键假设与风险
6. 资源需求
```

## 阶段卡口（决策门）

> 📌 按决策门规范执行，详见 [[产品方法论总览#阶段卡口 → 决策门规范]]。本卡口等级：**A 级**（默认不放行，可条件性放行）。默认要求 L2 证据。

进入循环二（方案与验证）之前，需要回答：

1. ✅ 我们的商业模式清晰，知道钱从哪里来？（A 级，L2 证据：单位经济粗算 + 商业模式画布）
2. ✅ 产品定位明确，知道为谁服务、不为谁服务？（A 级，L2 证据：定位陈述 + 用户画像）
3. ✅ 有清晰的北极星指标和阶段性 OKR？（B 级，L1 证据：指标定义即可，0→1 阶段可粗）
4. ✅ 路线图已与关键 stakeholder 对齐？（B 级，L1 证据：小团队 informal，大团队 formal）
5. ✅ 知道这个阶段做什么、不做什么？（A 级，L2 证据：Stop Doing List 明确）

带风险放行规则（0→1 阶段常用）：

```
0→1 阶段：商业模式与路线图可粗框架（B 级处理），但定位必须清晰（A 级不可降）
  ├── 带风险放行需风险接受人签字
  ├── 补偿措施：PMF 后必须回补商业模式细化
  ├── 复核日期：下次战略评审（通常 1 季度内）
  └── 自动失效：若 PMF 长期未达成，战略需重评
```
