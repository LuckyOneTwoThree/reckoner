# 方法论展开

这个模块的核心命题是：​「用数据减少决策中的猜测，而非用数据为决策做背书」​。是 PM 从经验驱动走向数据驱动的分水岭。

> 📌 定位升级：本模块已从"线性阶段中的第四站"调整为**横切层**。度量不是 PRD 写完之后才想的事，而是方案定义时就建立的"判断对错契约"。详见 [[产品方法论总览#主链路：非线性三循环模型]] 的循环二（方案与验证循环）。本模块与 [[10 决策内核]] 的假设验证、证据强度评估紧密耦合。

---

## 模块结构总览

```
产品度量与数据（横切层，贯穿方案设计与上线后评估）
├── 1. 指标体系设计
├── 2. 数据分析方法
├── 3. 实验设计与 A/B 测试
└── 4. 数据驱动决策
```

度量介入时机（横切层的体现）：

```
传统反模式：探索 → 商业 → 构思 → 度量（最后才介入）
横切层模式：
  ├── 循环一：定义北极星指标（与战略同步）
  ├── 循环二：方案定义时同步建立度量契约（PRD + 埋点 + Evals）
  └── 循环三：上线后持续度量，回流验证假设
```

## 1️⃣ 指标体系设计

目标：建立能真实反映产品健康度的指标网络，而非数字仪表盘

### 指标层级体系

```
北极星指标（1个）
    ↓ 拆解
一级指标 / L1（3-5个）
    ↓ 拆解
二级指标 / L2（驱动因子）
    ↓ 拆解
行动指标（可直接影响的操作变量）
```

北极星指标选择标准

- 反映用户从产品中获得的核心价值
- 与长期商业成功正相关（不是虚荣指标）
- 全团队可理解、可影响
- 既非纯收入指标，也非纯活跃指标

各类产品北极星指标参考

|产品类型|北极星指标|
|---|---|
|内容消费|内容消费时长 / 完播率|
|SaaS 工具|核心功能使用频次 / 活跃工作区数|
|电商交易|成交 GMV / 购买用户数|
|社交产品|发生互动的用户对数|
|教育产品|完课率 / 学习时长|

### 增长指标模型：从 AARRR 漏斗到 Growth Loops

> ⚠️ 框架升级说明：AARRR 是经典的线性漏斗模型，适合作为入门认知和初期搭建。但漏斗思维的天花板在于——它只能看到"流失"，看不到"复利"。本方法论推荐以 **Growth Loops（增长闭环）** 为主框架，AARRR 降级为辅助检查清单。这与 [[06 产品增长与运营#增长飞轮 vs 漏斗]] 的飞轮思维保持一致，避免方法论内部矛盾。

#### AARRR（辅助清单，用于查漏）

```
Acquisition    获客    → 新用户数、获客成本 CAC、渠道转化率
     ↓
Activation     激活    → 关键行为完成率、首次体验完成率
     ↓
Retention      留存    → 次日 / 7日 / 30日留存、Churn Rate
     ↓
Revenue        收入    → MRR、ARPU、LTV、付费转化率
     ↓
Referral       传播    → NPS、K 因子、邀请率
```

> 留存是最核心的指标——获客再好，留不住等于往漏桶里倒水

#### Growth Loops（主框架，用于设计复利系统）

> 核心转变：从"在漏斗某节点做优化"走向"设计自我强化的增长闭环"。每个 Loop 都有输入、行动、价值产出、再投入的循环。

```
Acquisition Loop（获客循环）
  ┌──────────────────────────────────┐
  │ 新用户加入                        │
  │   ↓ 体验核心价值                  │
  │ 产出内容/数据/社交行为             │
  │   ↓ 触达潜在用户                  │
  │ 吸引更多新用户加入 ──── 回到顶部   │
  └──────────────────────────────────┘
  关键指标：Loop 转化率、单次循环带来的新用户数、循环周期时长

Retention Loop（留存循环）
  ┌──────────────────────────────────┐
  │ 用户使用产品                      │
  │   ↓ 积累数据/关系/内容             │
  │ 产品对用户价值提升（更懂他）       │
  │   ↓ 转换成本上升                   │
  │ 用户更深度使用 ──── 回到顶部       │
  └──────────────────────────────────┘
  关键指标：单用户价值随使用时长增长曲线、累计投入量、流失临界点
```

#### 两类 Loop 的设计要点

```
Acquisition Loop 三要素：
  ├── 输入（谁/什么驱动循环启动）
  ├── 价值放大器（产品内什么机制让产出 > 投入）
  └── 输出（循环结束时产生什么可再投入的资源）

  典型形态：
  ├── 内容型 Loop：用户产出内容 → 吸引流量 → 新用户加入
  ├── 病毒型 Loop：用户邀请 → 新用户邀请更多人
  ├── 付费型 Loop：收入 → 再投入获客 → 更多收入
  └── UGC/网络效应 Loop：用户增多 → 产品价值提升 → 吸引更多用户

Retention Loop 三要素：
  ├── 累积价值（数据、关系、定制化、学习曲线）
  ├── 转换成本（离开会失去什么）
  └── 习惯触发（什么让用户反复回来）
```

#### 度量理念的根本转变

```
漏斗思维（AARRR）          闭环思维（Growth Loops）
─────────────              ─────────────
关注流失节点               关注复利杠杆
线性优化                    系统设计
看单次转化率                看循环周期与放大系数
获客是成本                  获客是 Loop 的副产品
增长靠持续投入              增长靠系统自我强化
```

> 实操建议：先识别你的产品当前有哪些 Loop（可能 1-2 个主力），量化每个 Loop 的转化率与放大系数，优先优化放大系数最高的 Loop，而非在漏斗某节点死磕。Loop 设计详见 [[06 产品增长与运营#增长飞轮 vs 漏斗]]

### 健康指标 vs 虚荣指标

```
虚荣指标（看起来好看）      健康指标（反映真实价值）
──────────────────────      ────────────────────────
总注册用户数          →      活跃用户数 / 留存率
页面浏览量            →      核心功能使用率
App 下载量            →      Day7 留存率
融资金额              →      单位经济模型（LTV/CAC）
媒体报道量            →      用户净推荐值 NPS
```

### 指标分类体系

输入指标 vs 输出指标

```
输入指标（可控）          输出指标（结果）
团队速度、发布频率    →    用户增长、收入
内容发布量            →    内容消费量
客服响应时长          →    用户满意度
```

> PM 应重点管理​输入指标​——输出指标是结果，输入指标才是杠杆

领先指标 vs 滞后指标

```
领先指标（预测未来）        滞后指标（确认过去）
功能使用率            →    用户留存
用户激活率            →    付费转化
搜索成功率            →    用户满意度
```

## 2️⃣ 数据分析方法

目标：从数据中找到行动信号，而非停留在描述现象

### 分析思维框架

数据分析五步法

```
1. 提出问题    → 明确分析目的，避免漫无目的探索
2. 获取数据    → 确认数据来源、口径、质量
3. 清洗加工    → 处理异常值、缺失值、口径对齐
4. 分析洞察    → 找规律、找异常、找因果
5. 行动建议    → 分析结论要指向具体决策
```

### 核心分析方法

漏斗分析

```
Step 1：曝光          10,000
Step 2：点击          3,000    (30%)
Step 3：注册          600      (20%)
Step 4：激活          180      (30%)
Step 5：付费          36       (20%)

→ 找最大流失节点，优先优化
→ 分人群、渠道、版本对比漏斗差异
```

留存分析

```
                D1    D7    D30
全量用户         40%   20%   10%
渠道 A 用户      55%   30%   18%   ← 高质量来源
新功能用户       45%   28%   15%   ← 功能有效果
```

> 留存曲线形态：快速下滑后趋于平稳 \= 找到核心用户群

用户分群分析（Cohort Analysis）

```
按注册时间分群，追踪各群组的行为差异
→ 识别产品改进是否真实提升了用户质量
→ 区分「产品变好了」还是「用户群变了」
```

路径分析

```
目标：找到高价值用户的行为路径
→ 高留存用户 Day1 都做了什么？（Aha Moment）
→ 流失前用户的最后行为是什么？
→ 付费用户的转化路径有何特征？
```

Aha Moment 定位

```
方法：对比留存用户 vs 流失用户的早期行为差异
例：
Facebook → 10天内添加7个好友
Twitter  → 关注30个账号
Slack    → 团队发送2000条消息
```

> 找到 Aha Moment，将其设计进产品 Onboarding 流程

### 数据异常处理

异常分析四问

```
1. 是真实异常还是数据问题？   → 先排查埋点、口径
2. 异常从什么时间开始？       → 与版本发布、运营活动对照
3. 哪些用户群体受影响？       → 分群下钻
4. 是什么行为导致了异常？     → 路径分析溯源
```

## 3️⃣ 实验设计与 A/B 测试

目标：用受控实验建立因果关系，而非相关关系

### A/B 测试完整流程

```
1. 提出假设         我们相信改变 X 会提升 Y
        ↓
2. 确定指标         主指标 + 护栏指标
        ↓
3. 计算样本量        显著性水平 α=0.05，统计功效=0.8
        ↓
4. 分流设计         随机、互斥、流量分配
        ↓
5. 运行实验         等待足够时间，不要提前停止
        ↓
6. 结果分析         统计显著性 + 实际业务意义
        ↓
7. 决策与推广        上线 / 放弃 / 继续迭代
```

### 实验设计关键要点

假设要具体可证伪

```
❌ 模糊：我们希望提升用户体验
✅ 具体：将注册流程从5步缩短到3步，
         预期将注册转化率提升15%
```

指标选择原则

```
主指标（Primary）：直接衡量假设是否成立
护栏指标（Guardrail）：确保没有损害其他核心指标
辅助指标（Secondary）：帮助理解实验机制
```

常见实验陷阱

|陷阱|描述|应对|
|---|---|---|
|偷看问题|结果好就提前停止|预设结束时间|
|新奇效应|用户因为新鲜感行为改变|观察长期数据|
|网络效应污染|对照组受实验组影响|隔离分群|
|样本偏差|分流不够随机|AA 测试验证|
|多重检验|测多个指标提升显著概率|Bonferroni 校正|

### 实验优先级决策

不需要 A/B 测试的情况

```
- 流量不足（无法达到统计显著性）
- 方向明确正确（修复明显 Bug）
- 改动太小（结果无意义）
- 需要快速响应的紧急问题
```

## 4️⃣ 数据驱动决策

目标：建立数据 → 洞察 → 行动的闭环，而非数据 → 报告 → 归档

### 数据驱动的决策框架

D.A.C.E. 循环

```
Define    定义问题与假设
    ↓
Analyze   分析数据寻找洞察
    ↓
Conclude  形成结论与建议
    ↓
Execute   执行并追踪结果
    ↓
（回到 Define）
```

### 数据洞察转化原则

从数字到故事

```
❌ 数据汇报：「本周 DAU 下降了 8%」
✅ 数据洞察：「本周 DAU 下降 8%，下钻发现主要来自
             iOS 新版本用户，与周二发布的 2.3.1 版本
             时间吻合，初步判断是新版本注册流程改动
             导致的激活率下降，建议回滚或紧急修复」
```

数据决策 vs 数据参考

```
适合数据决策：          适合数据参考：
A/B 测试结果            全新功能方向
功能迭代优化            用户体验设计
运营策略调整            战略级产品决策
```

> 数据能告诉你「发生了什么」，但「为什么」和「怎么办」需要判断力

### 建立数据文化的关键动作

PM 日常数据习惯

```
每日：核心指标 Dashboard 扫描（异常感知）
每周：功能模块数据 Review（进展追踪）
每月：完整数据分析报告（趋势与决策）
每季：指标体系复盘（目标校准）
```

数据需求与数据团队协作

```
PM 提供：               数据团队提供：
- 分析目标              - 数据可行性评估
- 业务背景              - 数据口径定义
- 决策时间节点          - 分析报告
- 假设方向              - 数据基础设施
```

## 埋点设计规范

> 「先想清楚要测量什么，再开发」——埋点是度量的基础设施

埋点四要素

```
事件（Event）：用户做了什么      如：点击按钮、完成注册
属性（Property）：在什么情况下   如：页面来源、用户类型
时间（Timestamp）：什么时候      如：事件发生时间
用户（User ID）：谁做的          如：匿名 ID / 登录 ID
```

埋点设计文档结构

```
埋点名称 | 触发时机 | 携带属性 | 分析目的
─────────────────────────────────────────
btn_register_click | 点击注册按钮时 | 页面来源、按钮位置 | 分析注册入口效果
```

## 阶段卡口（决策门）

> 📌 按决策门规范执行，详见 [[产品方法论总览#阶段卡口 → 决策门规范]]。本卡口等级：**A 级**（度量契约必须与 PRD 同步，不可后置）。本模块已是横切层，卡口主要约束"方案定义时是否同步建立度量契约"。

进入循环三（交付与增长）之前，需要回答：

1. ✅ 北极星指标和核心指标体系已定义清楚？（B 级，L1 证据：指标定义文档）
2. ✅ 关键功能的埋点方案已与 PRD 同步设计？（A 级，L2 证据：埋点文档 + 开发对齐）
3. ✅ 知道如何通过数据判断这个功能是否成功？（A 级，L2 证据：成功标准量化定义）
4. ✅ A/B 测试方案（如需要）已设计，假设明确？（A 级，L2 证据：实验设计 + 假设陈述）
5. ✅ 有清晰的数据 Dashboard 用于上线后监控？（B 级，L1 证据：Dashboard 框架）
6. ✅ **度量契约已接入 [[10 决策内核]] 的假设台账？**（A 级，L1 证据：假设与指标映射）

带风险放行规则：

```
度量契约不可跳过（A 级不可降）：
  ├── 没有"成功标准"的功能不进入开发
  ├── 带风险放行需 PM + 数据负责人双签
  ├── 补偿措施：开发期间补完度量契约，发布前必须就绪
  └── 复核日期：上线前最终检查
```
